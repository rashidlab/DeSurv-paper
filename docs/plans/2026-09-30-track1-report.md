### Design choices

- **Fixed-W refit uses the C++ flag, as the brief prefers.** Nothing couples W to H or beta except the W step:
  - zeta (`cox_scale`, the Cox-gradient rescale) exists only inside `update_W_damped_backtrack`, so skipping that step removes it entirely.
  - The W/H/beta renormalization happens in two places only: the initial normalization and the W step. Both are skipped. W is passed in already L2-normalized.
  - `update_H_cpp` depends on W only. Beta uses Z = X'W.
  - Stopping works unchanged: epsW is 0, so the loop stops on epsH.
  - The refit starts from the NNLS H0 and beta0 = 0 (the existing custom-init path) with the caller's `tol`/`maxit`. `desurv_consensus_fit` checks `identical(refit$W, consensus W)` and errors if they differ.
- **Constituent run:** `desurv_fit(..., seed = s, ninit = 1, parallel_init = FALSE)`, the code/04 `run_seed_fits` recipe. `init()` still runs with one start, so its `which.max` has nothing to choose from and no selection happens.
  - A failed or NaN run stops the call with the failing seeds listed. No run is dropped silently.
  - Non-converged runs are kept and recorded in `consensus$run_convergence`. The plan says only "each fit runs to convergence".
- **Family clustering uses PAM (`cluster::pam`, BUILD/SWAP, k families) on 1 - Pearson r, not average linkage.** Reasons:
  - Average linkage cut at k tends to spend a family on an isolated aberrant factor and merge two real families. PAM's medoid cost makes that unlikely; test T4 exercises this case.
  - PAM is deterministic with no seed.
  - It is the same algorithm as the frozen competing-mode check.
- **Canonical family order.** Families are ordered by the row of each consensus column's largest loading, then by that loading. This makes the output independent of run order and within-run column order, so tests 2 and 3 can demand bit-identical W.
- **Competing mode.** A family of 2 members is split into its two singletons, since PAM(2) needs at least 3 objects. A family of 1 member cannot have a mode. The medoid r is 1 - distance.
- **Outliers:**
  - Neighbours and the median/MAD are taken over all pooled R x k factors ("all factors' statistics").
  - Families with a competing mode are exempt, per the contract.
  - Removal is strict (`>` the threshold).
  - If outlier removal empties a family, `desurv_consensus_fit` errors.
- **Gate:**
  - Half-splits: for each R, `set.seed(split_seed)` then `n_splits` successive `sample(R)`. The caller's RNG state is restored afterwards.
  - Alignment: half 2 is aligned to half 1 by Hungarian on correlation, as specified. Half 1 is also mapped to the all-R consensus so that factor identities stay stable across splits.
  - `mode_pass` comes from the consensus on all R runs.
  - An estimator error on the full R runs or any half makes that R fail and is recorded in `$errors`.
  - Other outputs: `converged_R` (the smallest passing R whose 2R also passes), per-split betas, and median |delta training C| (descriptive only).

## Contract points needing an owner ruling (not redesigned)

1. **MAD scale.** Section 3 says "3 x MAD" without a constant. I used `stats::mad` (constant 1.4826, the SD-consistent scale), and it is recorded in `settings$mad_constant`. Raw MAD (constant 1) would remove more factors. This needs confirming, since the rule is frozen.
2. **Nearest-neighbour pool.** I read "its L nearest factors" and "all factors' statistics" as the pooled R x k set, not within-family. This needs confirming.
3. **Empty family after outlier removal.** The plan does not cover this. It is an error in the estimator and a recorded fail in the gate.
4. **Gate `mode_pass`.** It uses the all-R consensus only; competing modes found within halves are reported (`half_mode_fails`) but do not gate. A stricter reading would fail on any half-level mode.
5. **Split reseeding.** The seed is reset for each R; the plan's wording covers a single R.
6. **5th percentile** uses `quantile(type = 7)`. With 10 splits this interpolates between the lowest two values.
7. **`init()` best-by-training-C** (`R/init.R:180`) is untouched, as instructed. Its only caller is `desurv_fit` (`R/desurv_fit.R:276`), which reaches it whenever no `W0` is supplied. That path is still used with the default `ninit = 20` by `desurv_cv`'s final refits (`R/desurv_cv.R:422,453,469`). `desurv_alpha_warmstart` and `cv_cold` pass `W0`, so they bypass it. The consensus path reaches it only with `ninit = 1`, so it never selects.
8. **Top-gene tie-break change.** `desurv_get_top_genes` output (and so the scoring and `desurv_consensus_seed`) changes only when scores tie exactly at the ntop boundary. It is not version-gated.
